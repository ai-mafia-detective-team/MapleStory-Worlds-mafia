# 수사방 멀티룸 설계 (Instance Room 기반)

작성 2026-07-24. 조사·실측 기반. 착수 전 필독.

## 1. 문제

현재 "수사방"은 **레지스트리 메타데이터일 뿐 실제로 분리되지 않는다.**

- `_RoomService`는 `GetSharedMemory` 한 곳에만 쓰인다. 룸 생성·유저 이동·맵 전환이 없다.
- 모든 접속자가 같은 월드 인스턴스, 같은 `map01`, 같은 `MafiaGameLogic` 싱글턴을 공유한다.
- `playerRooms[uid]`는 방 id가 아니라 **물리 좌석 index 1~8**(`RoomSpawn_1..8`)이다. 이 8석이 유일한 물리 로비다.
- 레지스트리에 방이 3개여도 셋 다 같은 8석·같은 게임에 얹힌다.
- 방 입장은 `LobbyController:EnterInvestigationRoomLobby`가 UI 루트를 껐다 켜는 것뿐이다.

결과적으로 서로 다른 "방"의 플레이어가 같은 게임에 편입되고, 로비에 가만히 있는 유저가 모든 방의 시작을 막을 수 있었다(2026-07-24 `8ab1019`에서 `lobbyPresent` 로스터로 완화했으나, 구조 자체는 그대로다).

## 2. 결론 — MSW가 네이티브로 지원한다

`_RoomService`에 필요한 API가 전부 있다.

| API | 용도 |
|---|---|
| `GetOrCreateInstanceRoom(key, firstUserWaitSeconds=10)` | 방 생성/획득 |
| `CreateInstanceRoom(key, mapNames, firstUserWaitSeconds=10)` | 맵 지정 생성 |
| `MoveUsersToInstanceRoom(key, userIds, mapName)` | 방 멤버 일괄 이동 |
| `MoveUsersToStaticRoom(userIds, mapName)` | 로비 복귀 |
| `IsInstanceRoom()` / `RoomKey` / `StaticRoomKey` | 컨텍스트 분기 |
| `InstanceRooms` | 활성 방 목록 |
| `RequestSendEventToRoomAsync(event, targetRoomKey)` | 방 간 이벤트 |
| `RoomBeginEvent` / `RoomEndEvent` | 방 생명주기 훅 |

공식 문서에 **이 게임과 동일한 패턴**의 예제가 있다: "Ready를 누른 N명 이상을 새 인스턴스 룸으로 이동."

```lua
local instanceRoom = self:GetOrCreateInstanceRoom()
_RoomService:MoveUsersToInstanceRoom(instanceRoom.InstanceKey, toSendPlayers)
```

## 3. 실측 결과 (2026-07-24, play 모드 server_main)

```
[RS] StaticRoomKey=[__main__]
[RS] RoomKey=[__main__]
[RS] IsInstanceRoom=false
[RS] InstanceRooms count=0
[RS] users in this room=1
[Error] [LEA-3002] InvalidOperation : 인스턴스 맵으로 지정된 맵이 없습니다.  (owner: RoomService)
[RS] returned nil? true
```

- 현재 컨텍스트는 스태틱 룸이다.
- **인스턴스 맵이 0개라 인스턴스 룸을 만들 수 없다.** 이것이 유일한 차단 지점이다.
- 실패 시 예외가 아니라 `nil` 반환이므로 방어 코드로 처리 가능하다.

## 4. 선행 조건 (사람이 Maker에서 해야 하는 작업)

**게임 진행용 맵을 새로 만들고 `MapComponent`의 `InstanceMap`을 체크한다.**

- 현재 `map/`에는 `map01.map` 하나뿐이고 이것은 스태틱 맵이다.
- `map01`은 **로비 전용**으로 남긴다(스태틱 룸의 진입점).
- 게임 맵(8좌석 `RoomSpawn_1..8`, 방 경계 등)을 인스턴스 맵으로 분리한다.
- 이 작업은 맵 구조 속성이라 파일 직접 편집이 아니라 Maker UI에서 수행한다.

이 선행 조건이 끝나기 전에는 4단계 이후를 시작할 수 없다.

## 5. 목표 구조

| 지금 | 도입 후 |
|---|---|
| `map01` = 로비 + 게임 | `map01` = 로비 전용 (Static Room) |
| 방 = 레지스트리 항목 | 방 = 실제 Instance Room (`roomId`를 key로) |
| `_UserService.Users` = 월드 전체 | 인스턴스 룸 안에서는 그 방 멤버만 |
| `MafiaGameLogic` 싱글턴 1개가 모든 방 공유 | 방마다 독립 상태 |

**핵심 효과**: 인스턴스 룸 안에서 `_UserService.Users`가 곧 그 방의 멤버가 되므로, 로스터 오염 문제가 구조적으로 소멸한다. `8ab1019`에서 넣은 `lobbyPresent` 우회도 단순화할 수 있다.

## 6. 제약 (설계에 반드시 반영)

1. **인스턴스 룸 ↔ 인스턴스 룸 직접 이동 불가.** 반드시 스태틱 룸을 경유한다. "다른 방으로 바로 옮기기"는 구현 불가이며, 로비 복귀 후 재입장 흐름이어야 한다.
2. **포탈로 스태틱 ↔ 인스턴스 이동 불가.** 오직 `RoomService` API로만 가능하다.
3. **인스턴스 룸에 들어가려면 먼저 스태틱 맵을 거쳐야 한다.** 현재 로비 흐름이 이 조건을 이미 만족한다.
4. **`GetSharedMemory`는 "같은 월드 인스턴스 내 룸 간" 공유다.** 지금 레지스트리 설계는 그대로 유효하다. 다만 접속자가 월드 정원을 넘겨 **월드 인스턴스가 여러 개** 뜨면 방 목록이 인스턴스별로 쪼개진다. 그 시점에는 DataStorage로 승격해야 한다.
5. **`firstUserWaitSeconds`(기본 10초)** 안에 첫 유저가 안 들어오면 방이 파괴된다. 생성과 이동 사이 간격을 짧게 유지한다.

## 7. ⚠️ 기존 코드와 충돌하는 지점

`InvestigationRoomManager.PruneDisconnectedMembers`(2026-07-24 `8ab1019`)는 **"미접속 = 정리 대상"**으로 판단한다.

인스턴스 룸을 도입하면 **게임 중인 멤버는 인스턴스 룸에 있어 스태틱 룸의 `_UserService.Users`에 잡히지 않는다.** 그대로 두면 게임 중인 방의 멤버 전원을 유령으로 오판해 삭제한다.

→ **C-1 착수 시 `lastSeen` 타임스탬프 방식으로 반드시 교체한다.** 코드에도 해당 주석이 달려 있다.

## 8. 단계별 이행 계획

| 단계 | 내용 | 선행 |
|---|---|---|
| 0 | (사람) 인스턴스 맵 생성 + `InstanceMap` 체크 | — |
| 1 | 스모크 테스트: 인스턴스 룸 생성 → 유저 1명 이동 → `IsInstanceRoom()`·`_UserService.Users` 확인 | 0 |
| 2 | **`@Logic`/`@Sync`가 룸별로 분리되는지 실측 확정** (아래 9-1) | 1 |
| 3 | `PruneDisconnectedMembers`를 `lastSeen` 기반으로 교체 | — |
| 4 | 게임 시작 시 `GetOrCreateInstanceRoom(roomId)` + `MoveUsersToInstanceRoom` | 2, 3 |
| 5 | 게임 종료·퇴장 시 `MoveUsersToStaticRoom` | 4 |
| 6 | `RoomEndEvent`로 레지스트리에서 방 정리 | 4 |
| 7 | `lobbyPresent` 우회 단순화 | 4 |

## 9. 확인 필요 (문서만으로 못 가른 것)

1. **`@Logic`과 `@Sync`가 룸별로 분리되는가.** 공식 문서가 `StaticRoomLogic`/`InstanceRoomLogic`을 나눠 쓰고 `@Sync property IsPlaying`으로 인스턴스 룸 상태를 표시하는 예제를 보여주어 **강하게 시사**되지만, "Logic은 룸마다 별도 인스턴스" 라는 명시적 문장은 찾지 못했다. **이것이 아니면 설계 전체가 무너지므로 단계 2에서 반드시 실측한다.**
2. **`MoveUsersToInstanceRoom`의 인자 형식.** `.d.mlua`는 `table<string> userIds`인데 공식 예제는 `v.Name`(엔티티 이름)을 넘긴다. 실측 필요.
3. 인스턴스 룸 안에서 DataStorage·`_QAAchievementManager`·`_CollectionManager` 등 기존 매니저가 정상 동작하는지.
