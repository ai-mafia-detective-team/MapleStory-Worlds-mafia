# 비공개 출시 테스트 수정사항 및 역할 분배

비공개 출시 테스트에서 확인된 문제와 수정 우선순위, 담당자별 작업 범위 및 협업 경계를 정리한 문서입니다.

## 1. 수정 우선순위

### P0 — 반드시 먼저 수정

1. `LuaTableToJsonType.UnknownType` 오류
2. 방 퇴장·삭제 동기화
3. 유령 참가자 제거
4. 준비 상태 동기화 및 표시
5. 첫 번째 밤 행동 UI 미표시
6. 게임 종료 후 전체 상태 초기화
7. 두 번째 게임 시작 시 승리 화면 잔존

### P1 — 핵심 사용성

1. 채팅 발신자 표시
2. 게임 종료 후 대기실 복귀
3. 수사방 찾기 상태·입장 버튼 구조
4. 방장 퇴장 처리
5. 연결 끊김 처리

> 유령 참가자와 준비 상태 불일치를 방지하기 위한 최소한의 연결 종료 정리는 P0 범위에서 먼저 처리합니다. 사용자 안내 및 재접속 정책 등 확장 처리는 P1에서 진행합니다.

### P2 — 완성도

1. 봇 이름 변경
2. UI 버튼 위치 조정
3. 준비 완료 시각 효과
4. 상태별 안내 메시지
5. 게임 결과 화면 개선

## 2. 담당 경계

```text
[김도하]
로비 및 수사방 찾기 화면 디자인
        ↓
[노형래]
로비 기능
방 생성·검색·입장 검증
방 목록 Registry
        ↓
수사방 입장 성공
        ↓
[이지건]
수사방 대기실
준비·시작
게임 전체
결과·재게임
```

수사방 입장 성공 전까지는 김도하·노형래 영역이며, `MafiaLobbyHUD`가 표시되는 순간부터는 이지건 영역입니다.

## 6. UI 파일 소유권

기존 `TEAM_RULES.md`의 “모든 `.ui`는 김도하만 편집” 규칙은 새 담당 경계와 충돌하므로 다음과 같이 개정해야 합니다.

| 구간 | UI 소유자 | 파일 예시 |
|---|---|---|
| 수사방 입장 전 | 김도하 | `UI_Lobby.ui`, `UI_InvestigationRoomSearch.ui` |
| 수사방 입장 후 | 이지건 | `MafiaLobbyHUD.ui`, `MafiaDayHUD.ui`, `MafiaNightHUD.ui`, 승리 화면 |

- 담당자가 아닌 사람은 해당 `.ui`를 직접 수정하지 않습니다.
- UI 엔티티 이름과 경로는 스크립트 연결 계약이므로 변경 전에 관련 담당자에게 공유합니다.
- `.ui` 수정은 반드시 UIBuilder 또는 MSW Maker를 통해 진행합니다.
- `.ui` 충돌은 raw JSON이나 충돌 마커를 직접 편집해 해결하지 않습니다.

## 7. 방장 시작 규칙

기존 자동 시작 규칙 대신 다음 규칙을 기준으로 구현 여부를 팀에서 확정합니다.

1. 일반 참가자는 준비·준비 취소가 가능하다.
2. 최소 인원을 충족해야 한다.
3. 방장을 제외한 참가자가 모두 준비 완료 상태여야 한다.
4. 조건 충족 시 방장에게만 시작 버튼이 활성화된다.
5. 방장이 시작 버튼을 누르면 3초 카운트다운을 시작한다.
6. 카운트다운 중 준비 취소·퇴장·연결 종료가 발생하면 시작을 취소한다.

이 규칙을 채택하면 `Docs/GameFlow.md`와 실제 코드도 함께 갱신합니다.

## 8. 공용 연결 인터페이스

### 방 입장 성공 시 노형래 → 이지건

최소 전달 정보:

```text
roomId
ownerUserId
localUserId
players
maxPlayers
roomTitle
roomStatus
currentPlayerCount
```

### Registry 인터페이스

권장 API:

```text
GetRoomSnapshot(roomId)
JoinRoom(roomId, userId)
LeaveRoom(roomId, userId)
UpdateReadyState(roomId, userId, ready)
UpdateRoomStatus(roomId, status)
RemoveDisconnectedPlayer(roomId, userId)
```

책임 원칙:

- 노형래는 `InvestigationRoomManager.mlua`에 필요한 서버 인터페이스를 제공합니다.
- 이지건은 제공된 인터페이스를 호출하며 `InvestigationRoomManager.mlua`를 직접 수정하지 않습니다.
- 이지건은 `MafiaUIFlow.mlua`와 대기실·게임 상태를 담당합니다.
- 노형래는 `MafiaUIFlow.mlua`를 직접 수정하지 않습니다.
- 대기실 게임 판정의 원본은 이지건 서버 상태로 관리합니다.
- 검색 목록에 필요한 참가자 수·방 상태 요약만 Registry에 전달합니다.
- 공용 파일을 동시에 수정하지 않습니다.

1. 노형래: Registry DTO 및 `UnknownType` 오류 수정
2. 노형래: 고유 `roomId`와 방별 독립 상태 구현
3. 노형래: 입장·퇴장·삭제·연결 종료 API 확정
4. 김도하: 수사방 검색 상태 디자인 및 입장 버튼 구조 확정
5. 노형래: 검색 UI에 Registry 상태 연결
6. 노형래 → 이지건: 입장 성공 DTO와 호출 인터페이스 확정
7. 이지건: 대기실 참가자·방장·준비 상태 구현
8. 이지건: 첫 번째 밤 행동 UI 수정
9. 이지건: 게임 종료 전체 초기화 및 재게임 구현
10. 김도하: 실제 출시 해상도에서 입장 전 화면 검수
11. 이지건: 입장 후 게임을 두 번 연속 진행하며 검증

## 10. P0 완료 기준

최소 2명 이상의 실제 클라이언트로 다음 시나리오를 통과해야 합니다.

1. 방 생성
2. 다른 사용자 입장
3. 준비·취소 상태가 모든 클라이언트에 동기화
4. 퇴장 후 슬롯과 검색 목록에서 즉시 제거
5. 재입장해도 유령 참가자가 남지 않음
6. 첫 번째 밤에 역할 행동 UI 정상 표시
7. 게임 종료 후 기존 대기실 복귀
8. 준비·역할·생존·투표·밤 행동·승리 화면 초기화
9. 같은 방에서 두 번째 게임 정상 진행
10. 방장 퇴장과 연결 종료 후 방 상태 정상 유지

## 11. Git 및 검증 규칙

- 작업 시작 전 각자 브랜치에 최신 `origin/develop`을 반영합니다.
- 담당 파일이 겹치면 병합 전에 먼저 조율합니다.
- 커밋은 기능 단위로 짧게 나눕니다.
- 화면 전환이나 게임 진행 규칙을 바꾸면 `Docs/GameFlow.md`도 갱신합니다.
- Maker에서 `stop → refresh → build logs → play → runtime logs` 순서로 검증합니다.
- PR 본문에 테스트 시나리오와 결과, 남은 문제를 기록합니다.
